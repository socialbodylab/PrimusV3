## Fixes Applied In This Pass

### Consistency: Look Designer terminology

Replaced remaining visible `Look Mixer` / `Mixer preview` wording in the active UI with current terminology:

- Device preview checkbox now says `Include in preview`
- Preview target notices now say `Preview target: ...`
- Cue empty-state copy now points users to `Look Designer`
- Internal comments were updated where they added noise to terminology scans

Files touched:

- `V3_5/sender/web/index.html`
- `V3_5/sender/web/js/app.js`
- `V3_5/sender/web/js/look-mixer.js`
- `V3_5/sender/web/css/style.css`

### Clarity: friendly output type labels

Added a shared `outputTypeLabel()` helper and used it on visible output type surfaces checked in this pass.

Before, some UI areas showed raw IDs such as `short_strip`, `small_grid`, and `extra_long_strip`. After the patch, checked surfaces show friendly labels such as `Short Strip`, `Small Grid`, and `Extra Long Strip`.

Files touched:

- `V3_5/sender/web/js/app.js`
- `V3_5/sender/web/js/look-mixer.js`
- `V3_5/sender/web/index.html`

### Robustness: JSON API fallback

Unknown GET paths under `/api/` previously fell through to the static file handler and returned a plain-text `404`. They now return a JSON error response:

```json
{"error":"not found"}
```

Confirmed examples after the fix:

- `GET /api/not_a_real_route` -> `404 application/json`
- `GET /api/clips/../bad` -> `404 application/json`
- `GET /api/firmware/jobs/bad!` -> `400 application/json`

File touched:

- `V3_5/sender/server.py`

### Responsive safety: header wrapping

Added narrow-width rules for the main header so the brand, right-aligned nav items, and playback status can wrap instead of colliding on small screens. The playback metadata is hidden at narrower widths to keep the header compact.

File touched:

- `V3_5/sender/web/css/style.css`

## Findings To Carry Forward

### Medium: browser automation selectors are fragile

Observed during audit automation:

- `.sub-mode-toggle` matches both the Look Designer tabs and the Firmware V1/V2/V3 selector.
- Text locator `Cue Controller` matches both the nav item and page heading.
- `networkidle` is not a reliable wait condition because the app continuously polls state.

Recommended follow-up:

- Add stable `data-testid` attributes or role/label distinctions for the major mode tabs, sub-mode tabs, and critical controls.
- Use `domcontentloaded` plus visible-state waits for browser tests.

### Medium: docs still use some historical terminology intentionally and unintentionally

The web UI no longer exposes stale `Look Mixer` wording in the checked visible surfaces. Docs still contain mixed usage because `mixer.py` remains the backend module name and older documentation describes the previous UI vocabulary.

Recommended follow-up:

- Do a documentation terminology pass after the UI audit findings stabilize.
- Keep backend module names such as `mixer.py` where they are stable implementation details.
- Update user-facing docs to prefer `Primus Central`, `Look Designer`, `Clips`, `Looks`, `Cue Controller`, and `Firmware`.

### Low: Firmware terminology could be more specific

The Firmware panel is clear enough operationally, but it mostly says `Firmware` rather than `Receiver Firmware`. Since the sender app is now branded `Primus Central`, a future copy pass could clarify that this panel uploads receiver firmware.

Recommended follow-up:

- Decide whether the nav should stay concise as `Firmware` while panel headings use `Receiver Firmware`.

### Low: timeline side previews can be black at the current playhead

Canvas checks showed the Clips designer previews were nonblank. Timeline side previews were black at the current playhead for the loaded look, which can be valid if no colored segment is active at `t=0` or output is black.

Recommended follow-up:

- During the deeper Looks audit, test timeline side previews with a known fixture look containing an active colored segment at `t=0`.
- If black is expected, no code change is needed.
